# AGENTS.md — Tuto

## What is this

Tuto is a desktop app for learning technical concepts through an AI tutor. A lesson is a feed of short, readable cards generated by Claude — with syntax-highlighted code, Mermaid diagrams, and a per-concept Practice tab of fill-in-the-blank exercises. A card that has one line worth keeping carries a **takeaway**, shown under it (`docs/system/takeaways.md`). There is also a structured Notes document, **switched off** at `NOTES_ENABLED` in `src/bun/lesson-modes.ts`: it cost a prompt section in every turn and a routing field on every card, for a document that was not being read. The code and its prompt are still there; flip the flag to bring them back. It is a personal tool: instead of calling an API, it spawns the local `claude` CLI (Claude Code headless mode) as its AI backend. The product plan and design rationale live in `docs/app-plan.md`.

A lesson comes in one of three **modes**: a *topic* lesson is taught from what the model knows; a *codebase* lesson is taught from a project on this machine, which the tutor reads with read-only tools; a *lab* lesson is taught by having the learner install and run the thing here, one explained step at a time (`docs/system/lab-mode.md`). Everything mode-specific lives in `src/bun/lesson-modes.ts` and `prompts/modes/` — see `docs/system/lesson-modes.md` before adding a fourth, and before changing anything that affects what a turn costs.

**Two registries decide what a lesson is.** `LessonModeSpec` in `src/bun/lesson-modes.ts` says how its turns run — tools, timeout, cost ceiling, prefetch, working directory, opening message. The **model and the thinking effort are not there**: they are one pair in Settings, the same for every mode, because what a lesson costs is the learner's call (`src/bun/settings.ts`). `cardFeatures` on that same spec says what a card of it may carry — a takeaway, a hierarchy, a diagram, a caution, a cost, a requirements list — with the registry in `src/bun/card-features.ts` and one prompt fragment per feature in `prompts/features/`. Read `docs/system/card-features.md` before adding anything a card can show.

**The learner executes; the app only ever reads.** No lesson is given a tool that writes, runs, or reads this machine, and the only commands the app itself runs are the fixed, read-only machine probe in `src/bun/env-probe.ts`. A lab lesson's steps are the learner's to type. This is `docs/adr/0001-the-learner-executes-the-app-only-verifies.md`, and it is not a setting. A lab lesson alone may read the *web* (`WebSearch`, `WebFetch`) — `docs/adr/0002-fetch-documentation-in-the-app-not-through-mcp.md` — and the first turn of every lesson runs with no tools at all.

## Stack

- Shell: Electrobun — a Bun main process plus the OS's native WebView.
- UI: React + TypeScript, bundled by Vite; the WebView loads the build from `dist/`.
- Styling: Tailwind CSS v4 with shadcn/ui components (Base UI primitives, Hugeicons, Shiki for code, mermaid.js for diagrams).
- AI backend: the `claude` CLI, spawned per turn from the Bun process. It must be installed and authenticated on the machine.
- Persistence: plain files under the OS app-data dir — one folder per lesson holding `lesson.json` (and `notes.md` / `notes.json` when the notes feature is on). No database.
- Lint/format: Biome.
- Package manager: pnpm (required). Bun is the app runtime, not the dependency manager. Exact-version pinning is enforced by `savePrefix: ""` in `pnpm-workspace.yaml`.

| `scripts/` | Headless test scripts. `tutor-smoke.ts`, `codebase-smoke.ts`, `lab-smoke.ts`, `exercise-smoke.ts` and `prerequisite-smoke.ts` call the real model; `card-parse-test.ts` is token-free. |

## Commands

The app is a desktop binary, not a web server. All commands run through pnpm.

| Command | What it does |
|---------|-------------|
| `pnpm start` | Build the WebView and launch the desktop app from bundled views. |
| `pnpm dev` | Same, but with Vite HMR. HMR is opt-in via `TUTO_HMR=1`; auto-detecting a running dev server is intentionally disabled, so only `pnpm dev` uses it. |
| `pnpm smoke` | Run the tutor loop against the real `claude` model end to end. Spends tokens. |
| `pnpm smoke:codebase <path> [question]` | Same, for a codebase lesson: checks the tutor reads the project and cites it. Spends tokens. |
| `pnpm smoke:exercise` | Reject a bad exercise and check the replacement blanks real code. Spends tokens. |
| `pnpm smoke:lab [topic]` | Same, for a lab lesson: prints the machine report, then checks the plan card's requirements and that the steps arrive as commands to run. Spends tokens (~$0.20). |
| `pnpm smoke:prerequisite` | Check the "start one step back" offer fires where it should and stays quiet where it shouldn't. Spends tokens. |
| `pnpm smoke:verify` | The lab check allowlist (token-free — run it after touching `verify.ts`) plus judge verdicts on canned output. Spends a few cents. |
| `pnpm run test:parse` | Card-parse regression test over malformed replies. Token-free. |
| `pnpm typecheck` | `tsc --noEmit`. |
| `pnpm lint` / `pnpm format` | Biome check / format. |
